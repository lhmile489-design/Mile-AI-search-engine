### 任务 2：角标与高亮一一对应

**问题背景**

M3 的做法是点一个角标后，该信源下**所有被引句子**都高亮。M4 要求改为精确对应：只高亮被点击的那个角标所在的单句。

**关键设计决策**

角标在后端下发的原始 report 里的 UTF-16 偏移（`markerStart`）是唯一标识符。点击角标时把 `(index, markerStart)` 派发给 reducer，再在 `citations` 数组里精确找到该角标对应的那一条，取其 `highlight` 区间。

**为什么不能在渲染后的文本上计算偏移**

mdast 的 `text.value` 已经过转义和实体解码，字符位置和原文不一致。`markerOffsets()` 改用 text 节点的 `position.offset` 回到 vfile 里的原始 report，在原文片段上重新匹配，再用「编号一致 + 前后各 2 字符上下文一致」做配对校验；配不上返回 `null`，降级为只定位卡片不高亮句子。

**改动文件**

| 文件 | 改动内容 |
| --- | --- |
| `src/lib/citations.ts` | 新增 `markerOffsets()` 函数，把 text 节点里的角标映射回原始 report 偏移；remark 插件把偏移写入 `data-pos` 属性 |
| `src/lib/highlight.ts` | `collectRanges`（合并同一信源所有句子）替换为 `rangeForMarker`（只取 `index + markerStart` 都一致的那一条） |
| `src/components/search/MarkdownRenderer.tsx` | `CitationBadge` 读取 `data-pos` 得到 `markerStart`；激活判断同时检查 `index` 和 `markerStart`，同一信源其他角标不跟着亮；点击回调改为 `onCite(index, markerStart)` |
| `src/components/search/EvidenceDrawer.tsx` | 调用 `rangeForMarker` 取精确单句区间；上一次点击的高亮在下一次点击时清掉 |
| `src/store/actions.ts` | `OPEN_CITATION` 增加 `markerStart: number \| null` 字段 |
| `src/store/reducer.ts` | `activeCitation` 记录 `{ index, markerStart, nonce }` |
| `src/store/state.ts` | `activeCitation` 类型增加 `markerStart: number \| null` |
| `src/components/SearchApp.tsx` | `handleCite` 把 `markerStart` 传入 dispatch |

**降级行为**

- `markerStart` 为 `null`（转义、代码块、识别失败）：只定位并激活卡片，不高亮句子。
- 流式期间还没有 `citations`：只激活卡片（保持 M3 行为）。
- `highlight` 字段本身为 `null`：只激活卡片。

## 发现的其他问题（只记录不修复）

1. **转义的 `\[1\]` 会渲染成无偏移角标。** mdast 把它解析为普通文本 `[1]`，`remarkCitations` 会识别并渲染为角标，但 `markerOffsets` 因配对校验失败返回 `null`，表现为点击后只定位卡片、不高亮句子。LLM 几乎不输出转义方括号，暂不处理。

2. **后端句子切分问题（M3 汇报遗留）。** 高亮区间从 `1.`、`2.` 之类的数字后开始，是后端把有序列表切成了半句。前端偏移没有错，待后端 M4 任务 4 修复。

3. **同一句里多个角标产生相同高亮。** 同一段话被引用多次时，多个角标的 `highlight` 指向同一个区间。符合契约 §7.2，不是 bug，但视觉上有重复。

4. **`trace.cacheHit` 在 L1 命中时的界面表达未在 PRODUCT.md 里明确定义。** 当前做法：只在该阶段行后标注「（缓存命中）」，不显示全局 Badge。**需要主调度确认这个处理是否符合预期。**

5. **ResultToolbar 缓存标签依赖后端 `done.cacheHit`。** 若后端 M4 在回放时漏发该字段，前端不会自行推断，标签不出现。联调时需确认 `trace` 和 `done` 都带该字段。

## 知识点素材

- **精确角标高亮**：同一信源多次引用时，`(index, markerStart)` 是唯一标识符；`rangeForMarker()` 通过这对值找到单条 citation，只高亮该角标对应的句子。`src/lib/highlight.ts:rangeForMarker`。

- **偏移为何要回到原文计算**：mdast `text.value` 已被转义解码，字符位置和原始 Markdown 不一致。`markerOffsets()` 用 `text.position.offset` 回到 vfile 的原始文本切片，在切片上重新匹配，再用上下文校验配对，配不上返回 `null`。`src/lib/citations.ts:markerOffsets`。

- **缓存命中不改写耗时**：回放走同一条事件序列，前端无需为缓存新增任何分支；`cacheHit` 只用来加标签，`latencyMs` 始终展示本次真实耗时（决策 D4）。`src/store/reducer.ts`。

- **SSE 状态机对缓存的天然兼容**：回放时后端仍发出 `trace`、`sources`、`token`、`done` 事件，`reducer.ts` 的 `applyStreamEvent` 没有为缓存新增任何流转，前端组件无感知，只是多了一个 `cacheHit` 标签。
