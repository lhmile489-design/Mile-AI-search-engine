## 知识点素材

- **fetch + ReadableStream 解析 SSE 的粘包与半帧**：`src/lib/sse.ts` 的 `createSseParser` 维护行缓冲，按 `\n`、`\r\n`、`\r` 切行，空行表示一帧结束；一个 chunk 含多个帧、一个帧被切开都能还原。缓冲区以 `\r` 结尾时要等下一个字节，因为可能是 `\r\n`。UTF-8 多字节字符被切在 chunk 边界，靠 `TextDecoder.decode(chunk, {stream:true})` 缓存半个字符；测试里逐字节喂入验证无 U+FFFD。
- **为什么不能用 EventSource**：它只支持 GET，不能带 JSON 请求体；拿不到请求前的 400 JSON 响应；无法自定义看门狗和取消语义。
- **空闲看门狗与后端心跳配套**：后端每 10 秒发 `: ping` 注释行，因为 Next 内部代理 30 秒空闲会静默断开，浏览器收不到任何错误（`docs/依赖核实.md` §2.3）。前端 45 秒看门狗兜底，业务帧和注释行都刷新计时。测试用假定时器证明：12 次 10 秒心跳不超时，心跳停止后 45 秒触发。
- **AbortController 与迟到事件**：`sse.ts` 里 `dead` 标志让 `abort()` 之后所有回调静默；reducer 里 `runId` 再兜底一层，因为 rAF 合并和 `await` 期间都可能有已经在路上的事件。两层缺一不可：前者防网络层，后者防已入队的派发。
- **单一 reducer 的原因**：Esc、error、token 在不同状态下含义不同（`reducer.ts` 的 `ABORT`、`applyFailure`、`escapeAction`）。集中后可以用纯函数测试覆盖所有流转。`useSearchStore.ts` 让 `dispatch` 同步算出下一个状态，调用方能立即读到新的 `runId` 给流事件打标。
- **流式 Markdown 为什么整体重渲染**：增量边界可能切在 `[1`、`**` 或代码围栏中间，只有对累计文本整体解析才能得到正确结果，半截语法下一帧补全后自然修正。配合 token 按帧合并（rAF）和 `useDeferredValue` 降低开销。`[n]` 角标用 remark 插件在 mdast 的 text 节点上替换，代码、行内代码、链接内部不会误替换。
- **UTF-16 偏移与 `slice`**：后端 `highlight.start/end` 的单位就是 JS 字符串下标（码元），`passage.slice(start, end)` 直接可用。转成码点数组再切，会在 emoji 之后整体错位。
- **一个踩坑：组件类型必须稳定。** `react-markdown` 的 `components` 如果闭包了会变的值，每次状态变化都会让组件类型变化，整批角标被卸载重建，键盘焦点丢失。改用 context 传值，保持组件类型稳定（`MarkdownRenderer.tsx`）。
- **一个踩坑：Tailwind 会清除 `@layer components` 里未被扫描到的类名。** `.hljs-*` 只出现在运行时生成的 HTML，必须放在 `@layer` 之外。
- **一个踩坑：Playwright 里 `role=alert` 的第一个元素是 Next 的路由播报器**，不是业务提示条，选择器要用 `[role=alert].glass-float`。
- **mock 为什么只替换 fetch**：这样真实的 SSE 解析、事件校验和 45 秒看门狗在 mock 场景里照常运行，验证的是真实代码路径；生产构建靠 `NODE_ENV` 编译期常量把动态 import 整个消除。
