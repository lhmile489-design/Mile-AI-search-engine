## 知识点素材（供主调度整理学习文档）

1. **生成式 UI 为什么用 DSL 而不是 JSON**：LLM 生成代码的本质是「位置参数 + 命名引用」的语句序列（`root = Card(title, [c1], [r1])` / `c1 = Column(...)`）。DSL 让流式解析天然可行——每条语句独立、可截断在任意行，未闭合的语句 `partial:true` 而前面已完成的照常渲染；JSON 必须等整个 `}` 闭合才有合法值，流式中只能拿到残缺文本。`src/lib/openui.ts:66`（createLibrary）+ `openui-probe/probe.mjs` §stream（逐字符 push root 在第 N 字符首次出现）。
2. **流式期间容忍未闭合围栏的做法**：`createParser.parse` 对累计文本整体重解析，`meta.incomplete` 标记截断、`partial` 标记未写完的元素、`meta.errors` 只在结构真的非法时才非空。渲染策略是「`root` 有内容就渲染已有部分 + `incomplete` 时挂『正在生成』徽标；`root===null` 或 `errors` 非空才降级源码视图」——闪烁来自「流式中按『失败』处理」，正确做法是流式中按『部分成功』处理，只有流结束才能据此判失败。`OpenUiCard.tsx:50-90`。
3. **共识度为什么可能不显示**：`consensus.score` 是后端对「多源支持句子占比」的计算结果，不是固定文案——当后端算不出分（信源不足、句子无法对齐、模型没给分）时 `score` 是 `null`，前端必须整块隐藏而不是显示占位值（决策 D4 不放假数据）。显示时附带真实计数口径「N 句中 M 句有多源支持」，让数字可核对。`ConsensusBadge.tsx` + `types` 里 `consensus.score: number | null`。
4. **ElementNode 与求值树的差异**：`createParser` 返回的 `root` 是 `ElementNode` 树，嵌套 props（`columns`/`rows`/`stages`）仍是 `type:"element"` 的子节点而非纯对象——因为子组件可能要经 OpenUI 的 `renderNode` 解析成 React。自定义渲染（不走 `<Renderer>`）时必须先把这层壳剥掉（`unwrapOpenUi`），否则拿到的 `cells`/`stages` 是节点描述不是数据。`src/lib/openui.ts:80-105`。
