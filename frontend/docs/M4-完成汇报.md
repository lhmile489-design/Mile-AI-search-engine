## 发现的其他问题（只记录不修复）

1. **转义的 `\[1\]` 在前端仍会显示成角标（无偏移）。** 前端按渲染后的文本识别 `[n]`，转义的方括号在 mdast 里就是普通 `[1]`；后端用原文正则不会把它算作引用。表现：多出一个只能定位卡片、没有高亮的角标。LLM 很少输出转义方括号，暂不处理；如需要，可改为只在原文匹配成功的位置生成角标。
2. **后端句子切分问题仍在**（M3 汇报第 1 项，已排进后端 M4 任务 4）：本轮的真实验证里仍能看到高亮从小数点后开始（`0× with BF16 reaching up to 840 TFLOPs/s`、`3 PFLOPs/s, and (3)…` 都是被 `1.`、`2.` 之类切开的句子片段）。前端偏移没有错。
3. **后端同一句里的多个角标产生相同高亮。** 角标 0、2、4 都得到 `We develop three main techniques…`，说明这些角标在同一句或相邻句并且被匹配到同一个 passage 句子，符合契约 §7.2「一句里多个 `[n]` 各自生成一条」，只是多角标之间高亮重复。

## 知识点素材

- **缓存回放为什么对前端「无感」但耗时必须真实**：回放走的仍是同一条事件序列（`trace`、`sources`、`token`、`done`），前端只按事件更新状态，不需要为缓存写单独的分支，`reducer.ts` 的 `applyStreamEvent` 没有因为缓存新增任何流转。但如果后端把缓存里存的历史耗时原样发出来，界面上「总耗时」就是假的（决策 D4）。所以前端只展示事件里的 `latencyMs`、`elapsedMs`，`cacheHit` 仅用来加标签，不用来改数字。`isReplayingCache`（`state.ts`）也说明了一个细节：标签只来自事件里的 `cacheHit`，不靠耗时短来猜。
- **角标与句子一一对应为什么要用 `markerStart` 而不是文本匹配**：同一信源常被引用多次，句子内容可能相同或相似，按文本匹配会命中第一个而不是被点击的那个；`markerStart` 是后端给每个标记的唯一位置（UTF-16 偏移），`(index, markerStart)` 能唯一定位一条 `citations`（`highlight.ts` 的 `rangeForMarker`）。
- **如何保证偏移基于原始文本**：渲染前后的文本会因 Markdown 转义、实体解码、续行缩进而不同，直接在 `text.value` 上算下标会错位。`markerOffsets`（`citations.ts`）改用 mdast 节点的 `position.offset` 回到原文取片段、重新匹配，并用「编号一致 + 前后各两个字符一致」做配对校验；配不上就放弃（`null`），宁可少高亮也不给错偏移。偏移单位是 UTF-16 码元，与 JS 字符串下标一致，所以 emoji 和中文前缀都不会错位（`citations.test.tsx` 用代理对验证）。
- **一个设计点：配对要同时校验编号和上下文。** 转义的 `\[1\]` 在 `value` 里是 `[1]`，原文里它不是标记；如果只按顺序配对，会把后面真正 `[1]` 的偏移错配给它。测试里专门有「转义的 `\[1\]` 之后还有真正的 `[1]`」这一例。
- **稳定性验收为什么要统计 `pageerror` 而不只是看页面**：React 的渲染错误被 ErrorBoundary 吃掉后页面看起来仍然「有内容」，未捕获的异常、`console.error`（例如水合不一致、key 冲突、状态在已卸载组件上更新）都不会让页面白屏，只有统计 `pageerror` 和 `console error` 才能发现。`scripts/m4-e2e.py` 的 `Session` 在整个浏览器会话里收集这两类，并在稳定性阶段断言为空。
- **一个踩坑：Python 里用普通三引号字符串拼 TypeScript 代码，`\n` 会变成真换行。** 本轮用脚本批量改文件时因此破坏过一次 `scenarios.ts`，后来改用写文件工具整体重写；含转义字符的代码不要用 shell heredoc 加 Python 字符串来写。
