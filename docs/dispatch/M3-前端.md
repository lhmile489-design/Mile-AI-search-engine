## 本轮目标

把三屏状态机接到真实后端，跑通：**提交问题 → 检索推理态 → 流式研报 + 证据抽屉 → 历史恢复**。范围是 F01–F10（PRODUCT.md §5 第一张表）。F11–F15、F21–F25 属于 M5，本轮不做，但数据要留好位置（见「预留」）。

## 任务 1：基础设施

1. **依赖**：安装前设 `OPENUI_TELEMETRY_DISABLED=1`。本轮只装 Markdown 渲染相关：一个 React Markdown 渲染库 + GFM 支持；数学公式按决策 Q7 锁 `katex@^0.16`。具体包名先用 `npm view` 核实存在和版本，写进 `docs/依赖核实.md` 新一节（和 M0 一样标证据等级）。**不装 OpenUI 包**（M5）。
2. **http 封装** `src/lib/http.ts`：所有非流式请求走这一层。统一响应体 `{code, msg, data}`，成功码是整数 `200`；非 200 抛带 `code`、`msg` 的类型化错误。baseURL 用相对路径 `/api`。
3. **SSE 客户端** `src/lib/sse.ts`：`fetch` + `ReadableStream`，POST。
   - 帧解析：按空行切帧，识别 `id:`、`event:`、`data:`；以 `:` 开头的行是注释（心跳 `: ping`），忽略但要刷新「最近活动时间」。
   - 必须处理：一个 chunk 里含多个帧、一个帧被切在两个 chunk 之间、UTF-8 多字节字符被切在 chunk 边界（用 `TextDecoder` 的 `stream: true`）、`\r\n` 换行。
   - 请求前的 400（`code 40001/40002`）是普通 JSON 响应不是 SSE：先看 `content-type`，是 `application/json` 就按错误处理。
   - **45 秒空闲看门狗**：45 秒内既没有业务事件也没有心跳，就主动中止并报「连接超时」错误。
   - 返回可取消的句柄；`AbortController.abort()` 后不再触发任何回调（迟到的事件丢弃）。
   - 帧解析写成纯函数，补单元测试（见任务 5）。
4. **类型** `src/types/`：按契约 §3、§4、§7、§13 写 TypeScript 类型。`SourceCard`、六类事件载荷、`citations`、`HistoryCard`、历史详情。字段可空性照契约（「键存在、值可 null」和「键省略」要分清）。
5. **启动拉取**：`GET /api/config` 取 `focusModes/engines/scopes`，枚举不硬编码；`GET /api/suggestions` 取推荐问题，失败时用本地兜底 3 条（兜底文案放 `src/lib/fallback.ts`，不要和假数据混用：它只是推荐问题，不是结果数据）。

## 任务 2：状态机（PRODUCT.md §3）

- 集中在一个 reducer（`src/store/`）。组件只派发动作。
- 状态：`initial | retrieving | result`，`result` 内用 `generating` 布尔字段，不新增第四个状态。
- 流转逐条按 §3.1 实现，包括：第一个 `token` 切到 `result`；`Esc` 的三种行为（检索中回 `initial` 并保留问题 / 生成中留在 `result` 标「已中止」 / 已完成时关闭覆盖式抽屉）；出错的两种落点；任意状态点历史条目进 `result`。
- 进入 `retrieving` 前清空上一次的结果、轨迹、信源；同一时刻最多一个检索，提交新问题先中止旧连接。
- 事件到 store 的映射：
  - `trace` -> 更新对应阶段的状态与耗时（耗时只信 `elapsedMs`，不要自己用 `Date.now()` 算）；`rewriting end` 的 `detail.queries` 展示在时间轴；`degraded` 要在界面上能看到（小标注即可）。
  - `sources` `phase=raw` -> 按 `id` 去重追加到信源雷达；`phase=ranked` -> 整体替换为最终列表（按 `index` 升序），以 `ranked` 的分类为准。
  - `token` -> 追加到累计正文，**整体重新渲染**（增量边界可能切在 `[n]` 或 Markdown 语法中间）。
  - `done` -> `generating=false`，记录 `citations`、`latencyMs`、`stageTimings`，刷新历史列表。
  - `error` -> 按 `retryable` 决定是否显示「重试」；生成中途出错保留已生成内容，不撤回。
  - `related`、`takeaways`、`consensus`、`tokenStats` 先存进 store，**本轮不渲染**。

## 任务 3：三个屏幕（视觉全部走 DESIGN.md 令牌，禁止硬编码颜色）

1. **屏幕 1 首屏命令台**：品牌标志、Superbar（多行；`Enter` 提交、`Shift+Enter` 换行；空问题时提交按钮停用；去首尾空白后 1–500 字符，超长要有提示）、推荐问题 chip。请求固定传 `focusMode: "web"`、`engine` 取 `/api/config` 里第一个已配置的引擎、`scopeFilters: []`。首屏下方用小字展示一次快捷键说明。
2. **屏幕 2 检索推理态**：左 7 栏 HeronStepper（四阶段：改写检索词 -> 检索 -> 分类重排 -> 生成，每步状态与毫秒耗时，改写词展开）；右 5 栏 LiveSourceRadar（每个信源一行：favicon、域名、分类标签，未到达位置用骨架块）；「停止」按钮并提示可按 `Esc`；小于 1024px 上下排列。favicon 加载失败要有占位，不能出现破图。
3. **屏幕 3 研报与证据工作台**：左栏 Markdown 研报（流式渲染不闪烁），右栏 EvidenceDrawer 列出全部信源；顶部工具条显示问题、总耗时、信源数、「新检索」。小于 1024px 证据抽屉改为右侧滑出的覆盖式抽屉。`openui-lang` 围栏块本轮按**普通代码块**显示，不解析。
4. **引用角标（F05/F06）**：
   - 流式期间用正则 `\[(\d+)\]` 把正文里的 `[n]` 渲染为角标；`n` 超出已有信源范围时按纯文本显示。
   - 角标是可聚焦、可键盘操作的按钮。点击后证据抽屉滚动到第 `n` 个信源并高亮该卡片。
   - `done` 之后，用 `citations[].highlight`（`start/end` 是该信源 `passage` 的 **UTF-16 码元偏移**，直接 `slice`）在信源片段里高亮被引用的句子；`highlight` 为 `null` 或信源无 `passage` 时只高亮卡片。
   - 偏移只在 `done`（或历史快照）里有，所以流式期间点角标只定位卡片，这是预期行为，不是缺陷。
5. **信源卡片**至少显示：标题（链接，`rel="noopener noreferrer"`，新窗口）、域名、分类标签、`publishedAt`（格式化为本地日期，`null` 不显示）、`passage` 摘要。字段含义以契约 §4.1 为准。
6. **历史侧边栏（F09）**：`GET /api/history` 列表（标题用 `query`），点击用 `GET /api/history/{id}` 的快照直接恢复 `result`，**不重新检索**；快照里的 `report`、`sources`、`citations`、`stageTimings` 要能还原角标和高亮。支持删除（`DELETE`）。`Ctrl+B` 展开/收起。
7. **错误态（F08）**：网络断开、40001/40002、`error` 事件、看门狗超时，都显示「原因 + 下一步」的提示条（文案规则见 PRODUCT.md §8，例如「检索服务连接失败，请检查网络后重试」），可重试的带「重试」按钮，重试就是用同一问题重新发起。不允许出现空白页。
8. **键盘（F10）**：`Ctrl/Cmd+K`、`Ctrl/Cmd+B`、`Esc`、`Enter`、`Shift+Enter`，三个全局快捷键输入框内也生效并 `preventDefault`。
9. **工程约束**：SSE 解析在 `lib/`，状态机在 `store/`，组件只渲染；单文件不超 300 行；props 用 `Readonly<...>`；Markdown 渲染组件用 `next/dynamic` 懒加载；每个屏幕外包 ErrorBoundary。

## 任务 4：mock 的范围

主流程联调真实后端。`src/mocks/` 只用于真实后端**不方便稳定复现**的场景，且必须严格按定稿契约：

- 生成中途 `error` 事件（保留已生成内容的路径）
- 超过 45 秒的静默（看门狗）
- 不完整或带 `[99]` 幻觉角标的正文

做法：一个开发期开关（例如 `NEXT_PUBLIC_USE_MOCK=1`，仅 `/dev/*` 路由或开发模式可用）。**生产构建不得引用 `src/mocks/`**，汇报里附检查方法（例如在 `.next` 产物里搜 mock 文件名或特征字符串，贴命令与结果）。

## 任务 5：测试与验证

1. 单元测试（装一个测试框架，选型自定并在汇报说明）：SSE 帧解析（多帧同块、帧跨块、UTF-8 跨块、`\r\n`、注释行、未知事件名忽略）；reducer 的每条状态流转，尤其是：检索中 Esc 回 `initial`、生成中 Esc 保持 `result`、中止后迟到事件被丢弃、新检索清空旧数据；`[n]` 角标识别（超范围按纯文本）；`slice` 高亮在中文与 emoji（代理对）上偏移正确。
2. 联调（真实后端，端口 8000，`BACKEND_ORIGIN` 构建时设置，用完即停服务）：
   - 完整走一遍一次检索，截三个屏幕在 375 / 768 / 1024 / 1440 四个宽度的图，存 `docs/screenshots/M3/`。
   - 点一个角标，截证据抽屉定位与高亮图。
   - 检索中按 `Esc`：确认回到 `initial` 且问题保留；同时让主调度能复现后端不再继续调用外部 API（后端日志里该 session 之后无新请求）。
   - 生成中按 `Esc`：确认保留已生成内容并标「已中止」。
   - 从历史恢复一条记录，确认不触发 `/api/search/stream`（贴 Network 证据或服务端日志）。
   - 把后端停掉再提交一次：确认出现错误提示条而不是空白页。
3. 键盘走查：只用键盘走完「提交 -> 点角标 -> 关抽屉 -> 开历史 -> 恢复」，焦点必须始终可见。截几张图存 `docs/screenshots/M3/focus-*.png`。
4. UI 底线（DESIGN.md / 全局规范）：正文对比度 >= 4.5:1、focus 可见、四个宽度无横向滚动、`prefers-reduced-motion` 已适配、动效只用 `transform` / `opacity` 且 150–300ms、无 emoji、无硬编码颜色。
