## 任务 1：缓存命中标注（F20）

PRD F20：命中缓存时界面标注「缓存命中」，耗时显示本次真实耗时。

- 数据来自事件里的 `cacheHit` 字段（`trace` 与 `done` 都带），不要自己推断。reducer 里记录「本次是否缓存回放」。
- 展示位置：结果页顶部工具条的耗时旁边加一个小标签「缓存命中」（用 Badge，令牌配色）；检索推理态的 HeronStepper 在回放时也能看出来，例如在时间轴标题处同样显示该标签。回放很快（毫秒级），可能一闪而过，所以结果页工具条上的标签是主要展示位置。
- 耗时数字照常用后端下发的值（`latencyMs`、`elapsedMs`），不要因为是缓存就隐藏或改写。
- 历史恢复：历史详情里如果有 `cacheHit` 字段（见 §13.3 `cache_hit` 映射），同样显示该标签；没有该字段就不显示，不要猜。
- 单测：reducer 对 `cacheHit` 的记录、工具条在 `true` 与 `false` 下的渲染（可用 `renderToStaticMarkup`）。

## 任务 2：角标与高亮一一对应

M3 的实现是「点任一角标，高亮该信源下所有被引句子」。契约 §7.2 里每个 `[n]` 标记对应一条 `citations`（有 `markerStart/markerEnd`，正文 UTF-16 偏移），应该做到精确对应：

- 渲染正文时，给每个被识别的角标记下它在正文里的出现序号和 `markerStart`；`done` 之后用 `markerStart` 在 `citations` 里找到对应的那一条，得到该条 `highlight`。
- 点击角标：抽屉滚动到第 `n` 个信源，**只高亮该角标对应的那一句**，不再高亮同一信源下的其他句子。上一次点击的高亮要清掉。
- 流式期间（还没有 `citations`）或 `highlight` 为 `null`：只定位并标记卡片，保持 M3 行为。
- 边界：正文里被剔除的幻觉角标、相邻角标 `[1][2]`、同一句多个角标（各自独立）、角标出现在代码块或链接里（不识别，M3 已有处理）。
- 注意正文偏移是针对**后端下发的原始 `report`**，而前端渲染前可能有任何文本变换。如果你发现有变换会让偏移失效（例如对文本做了 trim 或替换），改成在原文上识别并记录，不要在变换后的文本上算偏移。写进汇报说明你怎么保证偏移对得上。
- 单测：多个角标指向同一信源时分别点击得到不同高亮；中文与 emoji 前缀下偏移仍然对；`highlight: null` 的降级。
