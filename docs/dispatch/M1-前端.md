## 任务 3：OpenUI 组件签名草案

研报里的交互卡片由前端定义组件库，后端按签名写 System Prompt，所以签名是跨端契约。参照教程的两种卡片：

1. **硬件基准对比卡片**：标题、列定义（key、标签、是否可排序、是否高亮列）、行数据；单元格文字里可以有 `[n]` 引用角标。
2. **执行流水线时钟卡片**：教程描述为「阶段涵盖 TMA 异步加载、Tensor Core 计算与 SMEM 写入，点击即可展开时延详情」。每个阶段有名称、耗时、说明。

要求：

- 产出 `frontend/docs/OpenUI组件签名-草案.md`：每个组件的名称、位置参数顺序、每个参数的类型（用 zod 描述）、是否必填；一段完整的、能解析的 DSL 示例；一段流式截断到一半的示例和预期解析结果。
- 在**项目外的临时目录**实测解析（和 M0 一样，安装时设 `OPENUI_TELEMETRY_DISABLED=1`，或用 `--ignore-scripts`），用 `createLibrary` + `defineComponent` 定义这两个组件，`createParser` 解析你的示例，贴 `errors` 结果。实测脚本放 `frontend/scripts/openui-probe/`，方便主调度复现；依赖不进 `frontend/package.json`。
- 如果 `library.prompt()` 能生成给模型的提示词片段，把输出贴进文档，后端写 System Prompt 时直接用。
- `[n]` 角标在 DSL 字符串里怎么表示、前端怎么识别，写清楚。
- 文末「需要主调度决定」：拿不准的签名设计和你的推荐。
