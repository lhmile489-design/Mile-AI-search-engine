## 问题 1（必修）：缓存回放写历史失败，`done.historyId` 恒为 `null`

**现象**：回放时日志报：

```text
缓存回放写库失败: ProgrammingError: ProgrammingError("Error binding parameter 10: type 'list' is not supported")
```

随后 `done.historyId = null`，`GET /api/history` 里没有 `cache_hit=1` 的新记录。契约 §11 和任务书都要求回放插一条新历史。

**根因**：`app/pipeline/stream.py` 的 `_replay_cache` 里 `db_row["trace_events"] = []`（约第 927 行）传的是 Python 列表，其余 JSON 字段都用了 `_json.dumps`，只有它漏了，SQLite 绑定不了列表。

**要求**：

- 修复，并决定 `trace_events` 存什么：应该存**本次回放自己发出的 trace 事件**（带 `cacheHit: true` 和本次真实耗时），序列化为 JSON 字符串。不要存空列表，也不要存原始计算那次的 trace。
- 写库失败不应该只是一行日志就悄悄吞掉后继续发 `done`。保持「写库失败不影响响应」的原则可以，但要用 `logger.error` 并带上 `type(exc).__name__` 和 `repr(exc)`（已做），同时确保这类低级错误有测试挡住。
- **补测试**（118 项没有覆盖到这条）：同一问题连续两次请求，第二次 `done.cacheHit == true` 且 `done.historyId` 不为 `null`；再查历史表，该记录 `cache_hit == 1`、`trace_events` 能被 `json.loads` 解析且每个元素 `cacheHit == true`；`GET /api/history/{id}` 能读出来。

## 问题 2（必修）：L1 命中时 `sources(raw).engine` 带 `(cached)` 后缀

**位置**：`stream.py` 约第 303 行返回 `f"{engine}(cached)"`，约第 379 行靠 `endswith("(cached)")` 判断。

**为什么要改**：契约 §2.1 与 §3.2 里 `engine` 是枚举（`tavily` / `deepseek`），前端按枚举展示和比较，带后缀会让标签和比较全部失效。你在汇报「需要主调度决定」第 2 项里问过，**决定：不要加后缀**。

**要求**：

- `sources raw` 的 `engine` 始终是真实引擎名；L1 命中用 `trace` 里的 `cacheHit: true` 表达（契约 §11：对应步骤标 `cacheHit: true`）。
- 内部判断「是不是 L1 命中」不要再靠字符串后缀，改成显式的布尔返回值。
- 同步修正降级判断逻辑（约第 379 行），确保 L1 命中不会被误判为降级。
- 补测试：L1 命中时 `engine` 等于真实引擎名且不含括号；L1 命中不触发 `searching degraded`。

## 问题 3（必修）：真实运行里看不到「客户端已断开」日志，且验收脚本没有断言

**现象**：主调度用真实服务测了一次：发起一个未缓存的检索，2 秒后客户端断开。结果是之后没有任何新外部调用（行为对），历史里也没有这条记录。但是**等了 25 秒，日志里始终没有** `客户端已断开，阶段=...，已取消 N 个在飞任务`。单测用假 provider 能看到这行，真实服务里看不到。

这说明单测和真实路径之间有差异。请你定位原因（例如：真实断开时 uvicorn 是怎样触发取消的、取消是不是落在了 `except asyncio.CancelledError` 之外的位置、流水线任务是被取消了还是自己因为别的原因停了），在汇报里写出根因，并修到真实运行里能看到这行日志。

**要求**：

- 在真实服务上复现并贴证据：启动服务，发起检索，2 秒后断开，贴日志里那一行，以及断开之后没有新的外部调用。
- 把 `scripts/smoke.py` 的中止验收改成**真的断言日志**（让服务日志落到文件，脚本读文件断言，或加一个只在测试用的诊断接口之外的办法）。不要再「PASS（需人工确认日志）」。支持用环境变量指定服务地址，不要写死 8000。
