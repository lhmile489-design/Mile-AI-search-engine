## 0. 通用约定

| 项 | 约定 | 依据 |
| --- | --- | --- |
| 基址 | 前端用相对路径 `/api`，Next.js `rewrites` 转发到 `http://127.0.0.1:8000` | PRD §8.1 |
| 普通接口响应体 | `{ "code": 200, "msg": "ok", "data": ... }`，`code` 是整数，成功码 `200` | 派发约定 |
| 失败响应体 | 同一结构，`code` 取 §12 错误码，`data` 为 `null` 或错误详情对象 | 派发约定 |
| HTTP 状态码 | 成功 200；参数错误 400；资源不存在 404；内部错误 500。前端以 `code` 为准 | 提议 |
| 流式接口 | `text/event-stream`，不套响应体 | PRD §8.1 |
| 时间 | ISO 8601 字符串，统一转成 UTC 并以 `Z` 结尾。信源发布时间精确到秒（`2025-08-27T00:00:00Z`），记录时间精确到毫秒（`2026-11-06T01:00:02.123Z`） | 派发约定 |
| 耗时 | 毫秒整数，字段名以 `Ms` 结尾 | 派发约定 |
| 分页 | 入参 `page`（从 1 开始）/ `pageSize`；出参 `total` / `records` | 派发约定 |
| 字段命名 | 接口 JSON 用 camelCase，数据库用 snake_case | 派发约定 |
| ID | 字符串 | PRD §8.1 |
| 鉴权 | 无，本机单用户；后端只监听 `127.0.0.1` | PRD §2.2 |
| 缺失值 | 算不出来的数一律是 `null`，不用固定值兜底 | PRD D4 |
| 字符串长度 | 后端说的「N 字符」按 Unicode 码点计（Python `len`）；下发给前端用来切字符串的偏移按 UTF-16 码元计（见 §7.1） | 提议 |

## 2. POST /api/search/stream

**功能**：发起一次检索，以 SSE 推送四个阶段的进度、信源、研报增量和最终结果。
**鉴权**：公开（本机）。
**请求头**：`Content-Type: application/json`，`Accept: text/event-stream`。

### 2.1 请求体

```json
{
  "query": "FlashAttention-3 FP8 内核吞吐基准",
  "focusMode": "web",
  "engine": "tavily",
  "scopeFilters": []
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `query` | string | 是 | 去首尾空白后 1–500 字符（PRD §8.2） |
| `focusMode` | string | 是 | `academic` / `code` / `web`（PRD F15） |
| `engine` | string | 是 | `tavily` / `deepseek`，必须是 `/api/config` 列出的已配置引擎 |
| `scopeFilters` | string[] | 否，默认 `[]` | **允许**的信源类别，取值见 §4.5。空数组表示不限。去重后最多 5 项（提议，语义见 §6.1） |

### 2.2 校验（建立流之前）

校验失败时**不建立 SSE**，直接返回 HTTP 400 + 统一响应体（派发约定）：

```json
{ "code": 40001, "msg": "query 去掉首尾空白后长度必须在 1 到 500 之间", "data": { "field": "query" } }
```

| 情况 | code | `data.field` |
| --- | --- | --- |
| `query` 为空或超长 | 40001 | `query` |
| `focusMode` 不在枚举内 | 40001 | `focusMode` |
| `scopeFilters` 含未知类别 | 40001 | `scopeFilters` |
| `engine` 不在枚举内 | 40001 | `engine` |
| `engine` 合法但没有配置密钥 | 40002 | `engine` |
| 请求体不是合法 JSON | 40001 | `null` |

### 2.3 响应头

```text
HTTP/1.1 200 OK
Content-Type: text/event-stream; charset=utf-8
Cache-Control: no-cache, no-transform
X-Accel-Buffering: no
```

`no-transform` 与 `X-Accel-Buffering: no` 沿用前端 M0 探针的写法（`frontend/docs/依赖核实.md` §2.1）；前端 M0 实测 Next 代理没有压缩 `text/event-stream`，事件逐条到达。

### 2.4 帧格式

```text
id: 7
event: sources
data: {"phase":"ranked","engine":"tavily","items":[...]}

```

- 每帧 `id: <n>`、`event: <名>`、`data: <单行 JSON>`，以空行结束（派发约定）。
- `id` 从 1 开始，同一条流内每个事件加 1，心跳不占编号。
- `data` 是单行 JSON：序列化时 `ensure_ascii=False`，字符串里的换行写成 `\n` 转义，所以一帧只有一行 `data:`。
- **不支持断点续传**：服务端忽略 `Last-Event-ID`。连接断开就等于中止，重试要重新发起检索（提议，理由：中止即释放任务，见 PRD F07）。

### 2.5 心跳

- 从响应头发出起，每 10 秒发一次注释行 `: ping\n\n`，直到流结束（派发约定）。
- 理由：前端 M0 实测 Next 内部代理的空闲超时是 30000ms，连续 30 秒无数据会断开上游，浏览器侧拿不到任何错误（`frontend/docs/依赖核实.md` §2.3）。研报生成前的阶段（改写 15s + 逐个子检索词检索 10s）可能超过 30 秒没有业务事件。
- 心跳是注释行，`EventSource` 和 `fetch` 流解析都会忽略；前端 M3 另做 45 秒空闲看门狗。

### 2.6 事件顺序

```text
 1 trace     rewriting  start
 2 trace     rewriting  end        detail.queries = 子检索词
 3 trace     searching  start
 4 sources   raw        子检索词 1 的结果（按完成先后，每个子检索词一批）
 5 sources   raw        子检索词 2 的结果
   ...
   trace     searching  degraded   （只在主引擎失败、切到备用引擎时出现）
   trace     searching  end
   trace     reasoning  start
   trace     reasoning  degraded   （只在分类服务失败、退回本地规则时出现；P0 只有本地规则，不会出现）
   sources   ranked     重排后的前 K 个，带编号、原文片段和分数
   trace     reasoning  end
   trace     generating start
   token     ...        研报增量，多条
   trace     generating end
   related              相关追问（收尾调用失败时不发）
   done                 最终结果；之后服务端关闭连接
```

- 任一阶段出错：发一条 `error` 后关闭连接，**不发 `done`**（派发约定）。
- 客户端断开：服务端在下一个检查点退出，不再调用任何外部 API，也不发任何事件（PRD F07）。检查点在每个阶段开始前、每个子检索词结果返回后、每个 LLM chunk 之后。
- 改写失败不算错误：降级为「原问题作为唯一检索词」，在 `rewriting end` 的 `detail.fallback` 标出（PRD §6.2）。

## 3. SSE 事件载荷

六类事件。字段表里「可空」表示值可以是 `null`，键始终存在。

### 3.1 `trace`：阶段进度

| 字段 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `step` | string | 否 | `rewriting` / `searching` / `reasoning` / `generating`（PRD §6.1） |
| `status` | string | 否 | `start` / `end` / `degraded`（PRD §8.3） |
| `atMs` | int | 否 | 从收到请求到发出本事件的毫秒数，`time.perf_counter()` 计时 |
| `elapsedMs` | int | 是 | 本阶段耗时，只在 `status=end` 时有值，其余为 `null` |
| `message` | string | 否 | 给人看的一句话，后端生成，如「改写出 4 个检索词」。前端可以不用 |
| `detail` | object | 是 | 结构随 `step` + `status` 变化，见下表 |
| `cacheHit` | bool | 否 | 本次是缓存回放时为 `true`（§11） |

`detail` 结构：

| step / status | detail 字段 |
| --- | --- |
| `rewriting` / `end` | `queries: string[]`（实际发给搜索 API 的子检索词，不含 `-site:` 后缀）；`fallback: bool`（改写失败、用原问题兜底时为 `true`）；`fallbackCode: int \| null`（失败原因，取 §12 错误码） |
| `searching` / `start` | `engine: string`（本次请求的引擎）；`queryCount: int` |
| `searching` / `degraded` | `from: string`；`to: string`；`code: int`（主引擎失败原因）；`queryIndex: int \| null`（哪个子检索词触发，从 0 开始） |
| `searching` / `end` | `enginesUsed: string[]`；`rawCount: int`（去重前条数）；`failedQueries: int[]`（两个引擎都失败的子检索词下标） |
| `reasoning` / `degraded` | `from: "model"`；`to: "rule"`；`code: int`（P0 不会出现） |
| `reasoning` / `end` | `inputCount`（去重前）、`dedupedCount`、`filteredCount`（范围过滤后）、`rankedCount`（进入生成的个数，≤ K）、`k`，均为 int |
| `generating` / `start` | `model: string`（`.env` 的 `LLM_MODEL`）；`sourceCount: int` |
| `generating` / `end` | `firstTokenMs: int \| null`（从本阶段开始到首个非空 token）；`charCount: int`（研报码点数） |
| 其余组合 | `null` |

示例（`rewriting end`，改写结果为示意，M2 实测后替换为真实输出）：

```json
{"step":"rewriting","status":"end","atMs":812,"elapsedMs":805,"message":"改写出 3 个检索词","detail":{"queries":["FlashAttention-3 FP8 kernel throughput benchmark","FlashAttention-3 Hopper FP8 TFLOPS","FA3 FP8 vs cuDNN attention"],"fallback":false,"fallbackCode":null},"cacheHit":false}
```

> 第一个子检索词取自 `docs/probes/tavily.json` 的真实 `query`；另外两个和耗时是示意值，本阶段没有跑改写，不能当实测。

### 3.2 `sources`：信源

两种 `phase`：

| 字段 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `phase` | string | 否 | `raw`：检索中逐批；`ranked`：重排后的最终列表，只发一次 |
| `engine` | string | 否 | 这一批来自哪个引擎；`ranked` 时为本次实际主要引擎 |
| `queryIndex` | int | 是 | `raw` 时为子检索词下标；`ranked` 时为 `null` |
| `items` | array | 否 | `raw`：`RawSource[]`（§4.1 精简版）；`ranked`：`SourceCard[]`（§4.1 完整版） |

- `raw` 批次之间可能出现同一个 `id`（不同子检索词命中同一页面），前端按 `id` 去重。
- `raw` 的 `category` 来自本地域名规则，检索阶段就能给出（信源雷达要显示分类标签，PRD §3.1）。接入 Jev 后 `ranked` 里的分类可能和 `raw` 不同，以 `ranked` 为准。
- `ranked` 的 `items` 按 `index` 升序，`index` 就是研报里 `[n]` 的 n。

`raw` 示例（单条，取自 `docs/probes/tavily.json` 的 `exclude_arxiv` 场景）：

```json
{"phase":"raw","engine":"tavily","queryIndex":0,"items":[{"id":"src_53d2a47e7517","title":"FP8 compute path not active in FlashAttention-3 on Hopper? · Issue #1848 · Dao-AILab/flash-attention · GitHub","url":"https://github.com/Dao-AILab/flash-attention/issues/1848","domain":"github.com","faviconUrl":"https://github.githubassets.com/favicons/favicon.png","engine":"tavily","category":"code","categorySource":"rule","publishedAt":"2025-08-27T00:00:00Z"}]}
```

`ranked` 示例见 §4.6。

### 3.3 `token`：研报增量

| 字段 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `delta` | string | 否 | LLM 返回的增量文本，原样转发，不拼接、不切分 |

- 空串 `delta` 不发（M0 实测第一个 chunk 的 `content` 是 `""`，`docs/probes/deepseek_llm.json`）。
- 增量边界由模型决定，可能切在 `[n]`、Markdown 语法或 `openui-lang` 代码块中间，前端按累计文本整体渲染。

```json
{"delta":"FlashAttention-3 在 Hopper 上的 FP8 路径"}
```

### 3.4 `related`：相关追问

| 字段 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `items` | string[] | 否 | 3–5 条追问（PRD F14），每条 ≤ 100 字符（提议） |

- 由收尾调用生成（§10.3）。收尾调用失败或解析不出 3 条以上时**不发**这个事件，`done.takeaways` 也为 `null`，流程照常结束。
- 示例内容需要真实生成，本阶段不编：`{"items":["...","...","..."]}`。

### 3.5 `done`：完成

| 字段 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `historyId` | string | 是 | 写入历史后的 id；写库失败时为 `null`（流程不因写库失败报错，记日志） |
| `latencyMs` | int | 否 | 从收到请求到发出 `done` 的毫秒数 |
| `stageTimings` | object | 否 | `{rewritingMs, searchingMs, reasoningMs, generatingMs, finalizingMs}`，均为 int。`finalizingMs` 是引用解析、高亮、收尾调用、写库的耗时，不单独发 `trace` |
| `firstTokenMs` | int | 是 | 从收到请求到首个非空 token；缓存回放时也是本次真实值 |
| `tokenStats` | object | 是 | 见 §10.4；没有任何 LLM 调用返回 usage 时为 `null` |
| `citations` | array | 否 | 见 §7.2：`[{index, markerStart, markerEnd, sentenceStart, sentenceEnd, highlight}]`，无引用时为 `[]` |
| `takeaways` | array | 是 | `[{ "text": string, "citations": int[] }]`，3–5 条（PRD F23）；收尾调用失败时为 `null` |
| `consensus` | object | 是 | `{ "score": number, "supportedSentences": int, "citedSentences": int }`；没有带引用的句子时为 `null`（PRD §6.6），见 §7.4 |
| `engine` | string | 否 | 请求的引擎 |
| `enginesUsed` | string[] | 否 | 实际用到的引擎 |
| `degraded` | bool | 否 | 本次是否发生过搜索引擎降级 |
| `sourceCount` | int | 否 | `ranked` 信源数 |
| `charCount` | int | 否 | 研报码点数 |
| `cacheHit` | bool | 否 | 是否缓存回放 |

```json
{"historyId":"hist_1793930000_a1b2c3d4","latencyMs":0,"stageTimings":{"rewritingMs":0,"searchingMs":0,"reasoningMs":0,"generatingMs":0,"finalizingMs":0},"firstTokenMs":0,"tokenStats":{"promptTokens":11,"completionTokens":37,"totalTokens":48,"cachedTokens":0,"calls":1},"citations":[{"index":1,"markerStart":97,"markerEnd":100,"sentenceStart":7,"sentenceEnd":101,"highlight":{"start":347,"end":576,"score":0.24}}],"takeaways":null,"consensus":{"supportedSentences":0,"citedSentences":2,"score":0.0},"engine":"tavily","enginesUsed":["tavily"],"degraded":false,"sourceCount":10,"charCount":0,"cacheHit":false}
```

> 示例里 `tokenStats` 取自 `docs/probes/deepseek_llm.json` 的真实 `usage`；耗时和计数写 0 是因为本阶段没有跑完整流水线，不是真实值，M2 冒烟后替换。`citations` 的真实示例见 §7.3。

### 3.6 `error`：出错

| 字段 | 类型 | 可空 | 说明 |
| --- | --- | --- | --- |
| `code` | int | 否 | §12 错误码 |
| `message` | string | 否 | 给用户看的原因，不含密钥、请求头、上游原始报文 |
| `step` | string | 是 | 出错阶段；收尾阶段出错为 `finalizing`；阶段外为 `null` |
| `retryable` | bool | 否 | 前端是否显示「重试」（PRD F08） |
| `upstream` | string | 是 | `llm` / `tavily` / `deepseek_search` / `classifier`；内部错误为 `null` |

```json
{"code":50204,"message":"生成研报超时（30 秒内没有收到首个 token）","step":"generating","retryable":true,"upstream":"llm"}
```

发完 `error` 立即关闭连接。生成阶段中途出错时，之前发过的 `token` 不撤回，前端保留已生成内容（`../PRODUCT.md` 状态机）。

## 4. SourceCard 统一结构

### 4.1 字段表

`ranked` 阶段下发的完整对象。`raw` 阶段下发它的精简子集，见下方标注。

| 字段 | 类型 | 可空 | raw 含 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | string | 否 | 是 | `src_` + SHA-256(归一化 URL) 前 12 位 hex，同一 URL 在任意检索中 id 相同（§4.2） |
| `index` | int | 是 | 否 | 引用编号 1..K，只在 `ranked` 有值；`raw` 为 `null` |
| `title` | string | 否 | 是 | 引擎返回的标题，原样 |
| `url` | string | 否 | 是 | 展示 URL：去掉 `#` 片段，其余保留（含 `www.`、query） |
| `domain` | string | 否 | 是 | 小写 host，去掉 `www.` 前缀，保留子域（`docs.vllm.ai`） |
| `faviconUrl` | string | 是 | 是 | Tavily `favicon` / DeepSeek `site_icon`，没有为 `null` |
| `engine` | string | 否 | 是 | `tavily` / `deepseek` |
| `category` | string | 否 | 是 | `preprint` / `code` / `spec` / `docs` / `blog`（§4.5） |
| `categorySource` | string | 否 | 是 | `rule` / `model`；P0 恒为 `rule`（§9） |
| `categoryRule` | string | 否 | 否 | 命中的规则标识，如 `domain:github.com`、`host-prefix:docs.`、`default` |
| `confidence` | number | 是 | 是 | Jev `confidence`；本地规则不产置信度，恒为 `null` |
| `publishedAt` | string | 是 | 是 | ISO 8601 UTC；拿不到为 `null`（§4.3） |
| `passage` | string | 是 | 否 | 清洗后的原文片段，≤ 1500 字符；两家都没有时为 `null`（§4.4） |
| `passageTruncated` | bool | 是 | 否 | passage 被长度上限截断过为 `true`；`passage` 为 `null` 时此键也为 `null` |
| `scores` | object | 否 | 否 | `{relevance, authority, freshness, final, weights}`，缺失项为 `null`（§5） |
| `engineSignals` | object | 否 | 否 | 引擎原始分数：Tavily `{score}`，DeepSeek `{rerankScore, authority}` |
| `matchedQueries` | int[] | 否 | 否 | 命中它的子检索词下标（去重合并时累加），§6.2 |
| `bibtex` | string | 是 | 否 | 仅学术信源；元数据不全时为 `null`（PRD F13） |
| `pdfUrl` | string | 是 | 否 | URL path 以 `.pdf` 结尾时与 `url` 相同，否则 `null`（提议） |

### 4.2 URL 归一化与稳定 id

归一化只用于去重和算 `id`，**不回写** `url` 字段（展示保留原始形态，只去 `#` 片段）。步骤（参照 `compute_examples.py` `normalize_url`）：

1. scheme、host 转小写；host 去掉 `www.` 前缀。
2. 端口：http:80、https:443 省略，其余拼回 host。
3. path：空则视为 `/`；长度 > 1 时去掉末尾 `/`。
4. query：丢弃键以 `utm_` 开头的参数，其余按键值原样保留。
5. **去掉 `#` 片段**（M0 实测 DeepSeek 返回 `...#2`、`...#1#1#1` 这类片段，同一页面会被片段拆成多条）。

`id = "src_" + sha256(归一化URL)[:12]`。理由：两家引擎返回的 `id` 字段都不稳定（Tavily 同一 URL 两次请求得到 `710f57-00` / `d89a90-00`），不能用来去重。

去重键 = 归一化 URL；同一键出现多次时保留 `score`/`rerankScore` 最高的一条，`matchedQueries` 合并下标。

### 4.3 发布时间 `publishedAt`

| 引擎 | 原字段 | 格式 | 处理 |
| --- | --- | --- | --- |
| Tavily | `published_date` | RFC 1123（`Sat, 20 Dec 2025 00:00:00 GMT`） | `email.utils.parsedate_to_datetime` → UTC → `Z` 结尾。键只在 `include_published_date=true` 时出现，M2 必须传 |
| DeepSeek | `date` | RFC 3339（`2026-03-03T16:00:00+00:00`） | `datetime.fromisoformat` → UTC |

字段缺失或值为 `null` → `publishedAt: null`（实测两家都会缺，PRD freshness 必须容忍缺失）。

### 4.4 原文片段 `passage`

| 引擎 | 来源字段 | 说明 |
| --- | --- | --- |
| Tavily | `content` | 摘录片段，实测原长 1437–2063 字符 |
| DeepSeek | `summary` | 面向模型的长摘要，实测原长 981–1129 字符（文档写 600–800，不可信） |

清洗规则（按序，参照 `clean_passage`）：

1. 去掉开头的 `2000 character limit reached` 行（Tavily `raw_content` 实测有此前缀，备份字段清洗时用同一条规则）。
2. 去掉整行是导航链接的行（`[Skip to content]`、`[Back to ...]`）和整行只有一个链接的行。
3. 删 Markdown 图片 `![..](..)`，链接 `[t](u)` 还原为 `t`。
4. 连续 3 个以上换行压成 2 个，去首尾空白。
5. 长度上限 1500 字符：截断时优先在最后一个句末标点或换行处断（距离上限 200 字符内），断点后 `passageTruncated=true`。

清洗后为空 → `passage: null`，前端只高亮卡片不高亮句子（PRD F06）。`raw_content`/`content`（DeepSeek 正文）不进 `passage`，留给生成阶段按上下文预算另算（§10.2）。

## 5. 重排分数口径

### 5.1 三个分量

| 分量 | 取值 | 来源 |
| --- | --- | --- |
| `relevance` | 0–1 | Tavily：`score`（实测 0.60–0.83，官方口径是纯相关性）。DeepSeek：`clamp(rerankScore / 3, 0, 1)`（实测 0–3，官方口径已混合权威度与时效，见 §5.3） |
| `authority` | 见 §4.5 表 | 本地域名规则映射的类别权威度，不依赖引擎 |
| `freshness` | `0.5 ^ (ageDays / 365)` | `publishedAt` 缺失时为 `null`；未来日期按 `ageDays ≤ 0 → 1.0` |

半衰期 365 天为**提议**（教程未定；一年内 0.5+，三年约 0.125）。

### 5.2 合成

```
final = w_rel * relevance + w_auth * authority + w_fresh * freshness
```

| focusMode | w_rel | w_auth | w_fresh | 依据 |
| --- | --- | --- | --- | --- |
| `academic` | 0.30 | 0.50 | 0.20 | PRD §6.3 |
| `code` | 0.40 | 0.40 | 0.20 | PRD §6.3 |
| `web` | 0.50 | 0.35 | 0.15 | PRD §6.3 |

**缺项权重重分**：`freshness` 为 `null` 时该分量权重按其余权重比例分摊（`compute_examples.py` 实测：无发布时间时 `w = {0.7692 rel, 0.5385 auth}` 归一后），`scores.weights` 里记重分后的实际权重，`freshness` 仍记 `null`，前端可区分「没算」与「算出来低」。`relevance`/`authority` 恒有值。

### 5.3 DeepSeek 的口径修正（提议，待主调度确认）

`rerank_score`（0–3）官方文档口径是**相关性 + 权威度 + 时效**的混合分，而 Tavily `score` 是纯相关性。如果对它也套 §5.2 权重，authority/freshness 会被算两遍，DeepSeek 的结果会系统性偏高。

**提议**：对 DeepSeek 结果，`relevance = clamp(rerankScore / 3)`，且权重固定 `{relevance: 1.0, authority: 0, freshness: 0}`，即 `final = relevance`；`scores.authority`/`scores.freshness` 仍按本地规则算出来展示（信息价值），但不进 final。`engineSignals` 保留原始 `rerankScore` 和 `authority`（0–4，缺失为 -1）供观测。

这样两家可比：`final` 都是「引擎认为的相关+质量综合分」，Tavily 的权威/时效由本地加权补，DeepSeek 的由它自己的 rerank 补。代价是 DeepSeek 侧放弃了本地权重调节能力；若主调度要两家用同一套本地权重，则需接受双重计分或反向拆出纯相关性（无文档依据，不推荐）。

## 6. 范围过滤

四层，顺序执行（PRD §6.3）：

| 层 | 时机 | 做什么 |
| --- | --- | --- |
| L1 检索侧 | 发请求前 | 按 `scopeFilters` 把排除类别翻译成引擎原生参数（见下） |
| L2 查询改写 | 发请求前 | DeepSeek 无 `exclude_domains`，把 `-site:` 后缀拼进查询词 |
| L3 本地过滤 | 拿到结果后 | 按 §4.5 域名规则再过滤一遍，是正确性的最终保证（L1/L2 都可能漏） |
| L4 展示 | `ranked` 事件 | `scopeFilters` 原样回写到 trace/detail，前端展示筛选状态 |

### 6.1 各引擎的 L1/L2

| 引擎 | L1 | L2 | 限制 |
| --- | --- | --- | --- |
| Tavily | `exclude_domains: [该类别全部域名]` | 无 | 实测支持，直接排除 |
| DeepSeek | 无对应参数 | 查询尾部拼 ` -site:d1 -site:d2 ...` | 查询总长 ≤ 128 字符（实测超限报错） |

**128 字符预算（实测值，M0）**：排除某一类所需的 `-site:` 后缀累计长度：preprint 124、code 147、spec 125、docs 97 字符。preprint/code/spec 三类单独就已接近或超过预算（还不含查询本体），**`-site:` 覆盖不完时必须靠 L3 兜底**。

提议规则：`-site:` 只拼「能完整放下的类别」，且优先放域名少、漏过滤代价高的类别；具体顺序留给实现（建议按类别后缀总长升序贪心，放不下的类别标注在 trace `detail.scopeFiltered=false` 之类字段提示 L3 承担了兜底——具体字段名实现时定）。**未确认**：官方是否支持 `-site:` 组合数上限、是否有更省字符的语法。

### 6.2 `matchedQueries`

同一 URL 被多个子查询命中时合并，`matchedQueries` 记录命中的子查询下标（0 起）。观测台用它解释「这条结果因哪些改写词而来」。

## 7. 引用、高亮与共识度

### 7.1 引用标记

研报正文中的 `[n]`，`n` 对应 `ranked` 事件的 `index`。后端生成 Prompt 强制要求「句末标注来源编号」；解析时用正则 `\[(\d+)\]`，`n` 超出 `sourceCount` 的视为幻觉引用，剔除该标记（同时 `trace` 记一条 `detail.hallucinatedCitation`——字段名实现时定）。

### 7.2 `citations`（`done` 事件下发）

```json
{"citations":[{"index":1,"markerStart":97,"markerEnd":100,"sentenceStart":7,"sentenceEnd":101,"highlight":{"start":347,"end":576,"score":0.24}}]}
```

- `markerStart/markerEnd`、`sentenceStart/sentenceEnd`：研报正文的 UTF-16 码元偏移（JS `slice` 直接用），由 `SENT_END` 正则切句。
- `highlight`：在被引源 `passage` 内定位最相关句子，`start/end` 同样是 passage 的 UTF-16 偏移，`score` 为词重叠分（`|A∩B| / |A|`，ASCII 词 + CJK 二元组，阈值 0.1，低于则 `highlight: null`）。
- 一句里多个 `[n]` 各自生成一条 citation，`sentenceStart/End` 相同。

### 7.3 `takeaways` 与 `consensus`

- `takeaways`：`[{text, citations: int[]}]`，finalization 调用的结构化输出，`citations` 为该要点引用的 SourceCard `index` 列表（PRD F23）；调用失败为 `null`。
- `consensus`：`{supportedSentences, citedSentences, score}`。`citedSentences` = 含合法引用的句子数；`supportedSentences` = 其中同时引用 ≥2 个**不同域名**信源的句子数；`score = supported / cited`（`cited=0` 时 `score: null`）。与教程的「100% 交叉验证一致」文案不同：这里是可复算的计数口径，不保证语义真一致（**提议**，PRD F-编号对应项是「共识度」但教程口径是固定文案，本项目按决策 D4 改为实算）。

## 11. 缓存与回放

- **键**：`sha256(normalize(query) | focusMode | engine | sorted(scopeFilters))`；normalize = 小写 + 压缩空白。改写词不进键（改写结果本身可缓存为另一层，键为主查询，**提议**）。
- **两层**（PRD）：L1 检索结果层（Tavily/DeepSeek 原始响应，TTL 较短，建议 5–15 分钟，**提议**）、L2 完整结果层（整条流水线的最终产物，TTL 较长，建议 1 小时，**提议**——具体值写进 `config.py` 前可再定）。
- **回放语义**：L2 命中时完整走一遍 SSE 事件序列（`trace` → `sources` → `token`*N → `related` → `done`），前端无感；但 `trace` 事件里标 `cacheHit: true`、各步 `elapsedMs` 为**本次回放的真实耗时**（毫秒级），`done` 里 `cacheHit: true` 且 `latencyMs`/`stageTimings` 是回放耗时而非原计算耗时——**不能用缓存里存的历史耗时**，否则界面上的「耗时」是假的（决策 D4）。
- L1 命中（检索结果缓存）则跳过检索、后面照常算，`trace` 对应步骤标 `cacheHit: true`。

| code | HTTP | retryable | 含义 | 触发 |
| --- | --- | --- | --- | --- |
| 200 | 200 | — | 成功 | — |
| 40001 | 400 | false | 参数校验失败 | query 空/超长、focusMode/engine/scopeFilters 非法 |

## 14. JSON / 命名约定

- JSON 一律 camelCase；DB 列 snake_case；Python 内部 snake_case，序列化层统一转换。
- 时间：`createdAt`/`updatedAt`/`publishedAt` 为 ISO 8601 带时区字符串（UTC `Z`）；`elapsedMs`/`latencyMs` 等为 int 毫秒。
- 缺失语义：算不出来 = `null`（键存在），不适用 = 键省略（如 `raw` 批次的 `index` 用 `null` 是因为 SourceCard 统一结构要求键存在——本条以 §4.1 字段表为准）。
