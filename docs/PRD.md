## 1. 背景与目标

### 1.1 要解决的问题

通用 AI 搜索对硬核技术问题有三个短板：

1. **过程不透明**：用户只看到转圈，不知道系统搜了什么、用了哪些信源、卡在哪一步。
2. **结论难追溯**：引用只是一个外链，用户还要自己去几万字的原文里找依据。
3. **信源质量不可控**：论文、规范、代码仓库、营销博客混在一起，用户无法限定范围。

### 1.2 产品目标

做一个本地运行的 AI 技术研报搜索引擎。用户输入一个技术问题，系统给出一篇带引用角标的研报，并且：

- 检索全过程可观测：改写了哪些检索词、抓到哪些信源、每个阶段耗时多少毫秒，全部摊开展示
- 每个断言可追溯到信源的原文段落，并高亮对应句子
- 用户可以限定信源范围（如排除预印本），过滤在后端真正生效，不只是界面隐藏
- 全程可用键盘操作

### 1.3 成功标准（第一版）

| 指标 | 标准 |
| --- | --- |
| 端到端可用 | 输入问题后能稳定拿到带引用的研报，连续 20 次检索无白屏、无卡死 |
| 引用有效 | 正文中的 `[n]` 全部能对应到真实信源；超出范围的编号按纯文本显示 |
| 过程真实 | 界面上的所有耗时、计数、分数都来自后端计算，代码中不存在写死的展示数字 |
| 中止可靠 | 任意阶段按 `Esc` 都能停止，后端在下一个检查点结束任务，不再调用模型和搜索 API |
| 历史可恢复 | 历史记录点开后不调用任何外部 API，直接恢复完整结果页 |

## 2. 用户与角色

### 2.1 目标用户

系统架构师、算法研究员、深度工程师。典型问题：

- 「NVIDIA Hopper TMA 异步拷贝指令优化」
- 「FlashAttention-3 FP8 内核吞吐基准」

### 2.2 角色与权限

本期是**单用户本地应用**，没有账号体系。

| 角色 | 能做 | 不能做 |
| --- | --- | --- |
| 本地用户 | 检索、阅读研报、查看证据、浏览和恢复历史、设置检索参数 | 无限制（本机即全部权限） |

- 不做登录、不做多用户隔离、不做管理后台（见 §12 决策 D3）。
- 后端只监听 `127.0.0.1`，不对局域网暴露。

## 3. 核心用户流程

### 3.1 主流程：发起一次检索

1. 用户打开首页，看到首屏命令台（品牌标志、Superbar 搜索框、推荐问题）。
2. 用户输入问题，可选：设置检索模式（academic / code / web）、信源范围、搜索引擎。按 `Enter` 提交。
3. 界面进入**检索推理态**：
   - 左侧步骤时间轴依次点亮四个阶段：改写检索词 → 检索 → 分类重排 → 生成；每个阶段结束时显示耗时
   - 改写阶段结束后，时间轴下展开改写出的子检索词
   - 右侧信源雷达随检索进度追加信源行，显示域名和分类标签
4. 收到第一段研报文字后，界面切到**结果工作台**，研报继续流式输出。
5. 生成结束后：顶部控制条显示「4/4 阶段完成 · 总耗时 · 信源数」；正文下方出现相关追问；本次检索写入历史。

### 3.2 阅读与核验证据

1. 用户点击正文中的角标 `[3]`。
2. 右侧证据抽屉滚动到第 3 个信源，卡片展示原文段落，被引用的句子用琥珀色高亮。
3. 用户可以复制 BibTeX（仅学术信源）、打开原文链接、打开 PDF（有的话）。
4. 点击证据抽屉里的信源卡片，正文中引用该信源的角标同步高亮（双向联动）。

### 3.3 回看推理过程

1. 结果页顶部点击「观测台」。
2. 切到推演全景观测台：左侧完整复原四个阶段的耗时、子检索词、阶段说明；右侧是本次全部信源的分类雷达。
3. 点击任一信源卡片，切回研报，证据抽屉定位到该信源。

### 3.4 中止与出错

- 检索阶段按 `Esc`：断开连接，回到首屏，输入框保留原问题。
- 生成阶段按 `Esc`：停在结果页，保留已生成内容，标注「已中止」。
- 任何阶段出错：显示原因和「重试」按钮，不出现空白页。
- 中止和出错的检索不写入历史（见 §12 决策 D6）。

### 3.5 恢复历史

1. `⌘B` 展开侧边栏，看到历史检索列表（按时间倒序）。
2. 点击一条，界面直接恢复到该次检索的结果页，包括研报、信源、证据、观测台数据。不调用任何外部 API。

## 6. 后端检索流水线

### 6.1 总览

```text
POST /api/search/stream
  │
  ├─ 0. 参数校验 → 计算缓存键 → 命中则回放缓存（F20）
  │
  ├─ 1. rewriting   改写检索词（LLM）                 → trace
  ├─ 2. searching   子检索词并发检索 + 引擎降级         → trace, sources（逐批）
  ├─ 3. reasoning   去重 → 范围过滤 → 分类 → 重排 → 取前 K → trace, sources（最终列表）
  ├─ 4. generating  研报流式生成（LLM）                 → trace, token...
  │
  └─ 收尾：引用解析 → 句子高亮定位 → 要点/追问/共识度 → related, done → 写入历史与缓存
```

- 每个阶段前后都检查客户端是否断开（`request.is_disconnected()`），断开即释放任务。
- 每个阶段用 `time.perf_counter()` 计时，开始和结束各发一条 `trace`。
- 任一阶段异常时发 `error` 事件并结束连接，不发 `done`。

### 6.2 阶段 1：改写检索词

- 输入：原问题、检索模式、信源范围。
- 输出：3–5 个子检索词。
- 范围约束在这一步注入（过滤第 1 层）：例如未勾选预印本时，Prompt 明确禁止生成含 `arXiv`、`paper`、`survey` 的检索词。
- 模型调用失败时降级为「原问题作为唯一检索词」，时间轴标注降级。

### 6.3 阶段 2–3：检索、过滤、分类、重排

**检索引擎抽象**：定义 `SearchProvider` 基类，统一入参（检索词、排除域名、返回条数）和出参（标题、URL、摘要、原文片段、发布时间、相关性分）。

| 引擎 | 状态 | 说明 |
| --- | --- | --- |
| Tavily | 主引擎，未确认 | 教程用 `advanced` 深度与 `exclude_domains` 参数，需实测请求与返回字段 |
| DeepSeek 搜索端点 | 未确认 | 教程称「直连 DeepSeek 搜索端点」，DeepSeek 是否提供公开搜索 API 需核实；不存在则本项不做 |

**范围过滤四层**（F21，P0 阶段先实现第 3 层的域名规则框架，P1 接入界面）：

| 层 | 位置 | 做法 |
| --- | --- | --- |
| 1 | 改写 | Prompt 禁止生成被排除类别的检索词 |
| 2 | 搜索 API | 请求参数传 `exclude_domains` |
| 3 | 结果合并 | `is_source_allowed_by_scopes()` 按域名黑白名单丢弃 |
| 4 | 分类后 | 分类结果落到被排除类别的信源直接剔除；非学术信源清空 `bibtex` |

**分类**（F18）：

- 5 个类别：学术预印本、代码仓库、规范与协议、框架官方文档、技术博客与评测。
- 主方案：QuickRouter `jev-1.14.0`（未确认，接口地址、入参 `choices`、出参 `choice` / `probability` 均需实测）。
- 兜底：本地域名规则（如 `arxiv.org` → 预印本，`github.com` → 代码仓库，`rfc-editor.org` → 规范）。主方案超时（2.5s）或失败时使用。
- 按 URL 做进程内缓存。
- 主方案未核实前，P0 只用本地规则，接口留好替换位。

**重排**（F19）：

```text
final_score = w_rel × relevance + w_auth × authority + w_fresh × freshness
```

| 模式 | w_rel | w_auth | w_fresh |
| --- | --- | --- | --- |
| academic | 0.30 | 0.50 | 0.20 |
| code | 0.40 | 0.40 | 0.20 |
| web | 0.50 | 0.35 | 0.15 |

- `relevance`：搜索引擎返回的相关性分；缺失时记为缺失并在界面标注，不用固定值填充（教程用 `0.8` 兜底，本项目不采用）。
- `authority`：按分类和域名白名单计算，规则表放配置文件。
- `freshness`：按发布时间衰减，无发布时间记为缺失。
- 缺失项的权重按比例分给其他项。
- 取前 K 个信源进入生成，K 默认 10，可配置。

### 6.4 阶段 4：研报生成

- 模型：DeepSeek API。教程用的模型名 `deepseek-flash` 未确认，以 DeepSeek 官方文档当前可用模型为准，模型名放配置。
- 输入：原问题 + 前 K 个信源（带编号、标题、原文片段）。
- 输出要求（写进 System Prompt）：
  - Markdown 正文，断言后用 `[n]` 标注信源编号
  - 评测类数据输出 OpenUI DSL 代码块（P1）
  - 结构化输出要点 3–5 条与追问 3–5 条（P1）
- 生成中每一段增量发 `token` 事件。

### 6.5 收尾：引用与高亮

- 解析正文中的 `[n]`，统计每个信源被引用次数，编号越界的标记为无效。
- **句子高亮定位**：对每处引用，取引用所在句子，在对应信源的原文片段中找最相近的句子，下发其字符起止位置。算法先用词重叠度，效果不够再换（待实测）。找不到时不下发，前端只高亮卡片。
- 结果写入 `done` 事件。

### 6.6 共识度（F25，P1）

教程中共识度是写死的字符串 `"100% 交叉验证一致"`，本项目不采用。初版算法（待确认）：

```text
共识度 = 被 ≥2 个不同域名信源同时支持的引用句数 / 带引用的句子总数
```

- 没有带引用的句子时不计算，界面不显示。
- 算法写进对接文档，界面在数值旁提供说明入口。

### 6.7 缓存（F20）

| 层 | 内容 | TTL | 键 |
| --- | --- | --- | --- |
| 流水线缓存 | 完整结果（研报、信源、要点、追问、高亮） | 600s | `engine + mode + scopes + query` 归一化后哈希 |
| 子检索词缓存 | 单个子检索词的搜索结果 | 600s（待确认） | `engine + scopes + sub_query` |

- 进程内内存实现，用 `asyncio.Lock` 保证并发安全，不引入 Redis。
- 命中流水线缓存时，按原事件顺序回放 SSE，**但 `trace` 中的耗时是本次回放的真实耗时**，并带 `cacheHit: true`。不能把上次的耗时当作本次耗时展示。

### 6.8 持久化（F09）

- SQLite，Python 标准库 `sqlite3`，所有读写用 `asyncio.to_thread` 包装，不阻塞事件循环。
- 只保存成功完成的检索。
- 表结构草案见 §7，正式版输出到 `docs/数据库设计.md`。

## 7. 数据模型（草案）

### 7.1 `search_history` 表

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | TEXT PK | 是 | `hist_{unix秒}_{8位随机}` |
| `query` | TEXT | 是 | 原问题 |
| `focus_mode` | TEXT | 是 | `academic` / `code` / `web` |
| `engine` | TEXT | 是 | 实际使用的引擎（降级后记录降级后的值） |

## 8. 接口规划（草案）

正式字段以后端定稿的 `docs/接口设计.md` 为准，前端只按定稿版 mock。

### 8.1 通用约定

| 项 | 约定 |
| --- | --- |
| 基址 | 前端统一用相对路径 `/api`，开发环境由 Next.js `rewrites` 转发到 `http://127.0.0.1:8000` |
| 普通接口响应体 | `{ code, msg, data }`，成功码 `200`（待后端定稿确认） |
| 流式接口 | `text/event-stream`，不套响应体；错误用 `error` 事件 |
| 时间 | ISO 8601 字符串；耗时统一为毫秒整数 |
| ID | 字符串 |
| 鉴权 | 无（本机单用户） |

### 8.2 接口清单

| 方法 | 路径 | 用途 | 优先级 |
| --- | --- | --- | --- |
| POST | `/api/search/stream` | 发起检索，返回 SSE | P0 |
| GET | `/api/history` | 历史列表（分页 `page` / `pageSize`，出参 `total` / `records`） | P0 |
| GET | `/api/history/{id}` | 单条完整快照 | P0 |
| GET | `/api/suggestions` | 首屏推荐问题 | P0 |
| GET | `/api/config` | 可用引擎列表、可用范围类别、各模式说明（前端据此渲染选项，不硬编码） | P1 |
| GET | `/api/health` | 健康检查，含各外部依赖是否已配置 | P0 |

`POST /api/search/stream` 请求体：

```json
{
  "query": "FlashAttention-3 FP8 内核吞吐基准",
  "focusMode": "web",
  "engine": "tavily",
  "scopeFilters": []
}
```

校验：`query` 去首尾空白后 1–500 字；枚举值不合法返回 400。

### 8.3 SSE 事件

| 事件 | 时机 | 载荷要点 |
| --- | --- | --- |
| `trace` | 每阶段开始和结束 | `step`、`status`（`start` / `end` / `degraded`）、`elapsedMs`、`message`、`detail`（如子检索词）、`cacheHit` |
| `sources` | 检索中逐批；重排后一次最终列表 | `phase`（`raw` / `ranked`）、`items: SourceCard[]` |
| `token` | 生成中 | `delta` |
| `related` | 生成后 | `items: string[]` |
| `done` | 全部完成 | `historyId`、`latencyMs`、`stageTimings`、`tokenStats`、`citations`、`takeaways`、`consensusScore` |
| `error` | 任一阶段出错 | `code`、`message`、`step`、`retryable` |

与教程的差异：教程 `trace` 只在阶段开始时发、耗时在 `done` 里一次性给出，`sources` 只在重排后发一次。本项目要求每阶段结束就发耗时、检索中逐批发信源，这样时间轴和信源雷达才能实时更新。新增 `error` 事件。

## 9. 非功能需求

### 9.1 性能（目标值，M1 后按实测调整）

| 指标 | 目标 |
| --- | --- |
| 提交到首个 `trace` 事件 | < 300ms |
| 提交到首个 `token` | P50 < 8s（待实测） |
| 缓存命中完整回放 | < 1s |
| 历史恢复 | < 200ms |
| 首屏 JS（gzip） | < 200KB，重组件懒加载 |

教程里的「Jev 50ms 级分类」「耗时 0.6s」等数字来自作者环境和截图，未经验证，不作为本项目指标。

### 9.2 可靠性

- 每个外部调用都有超时：改写 15s、单次搜索 10s、分类 2.5s、生成首 token 30s（均可配置，待实测）。
- 外部依赖失败按 §6 的降级路径处理；无降级路径时发 `error`。
- 前端每个屏幕包一层 ErrorBoundary。

### 9.3 安全

- DeepSeek、Tavily、QuickRouter 的密钥只放后端 `.env`（加入 `.gitignore`），提供 `.env.example` 占位。前端不接触任何密钥。
- 后端只监听 `127.0.0.1`。
- Markdown 渲染禁用原始 HTML，外链加 `rel="noopener noreferrer"`，防止信源内容注入脚本。
- 日志不打印密钥与完整请求头。

### 9.4 可观测

- 后端结构化日志：每次检索一个 `request_id`，记录各阶段耗时、引擎、降级、缓存命中、中止点。
- 中止时记录「在哪个阶段退出」，作为 F07 的验收证据。

### 9.5 可访问性与视觉

按 `DESIGN.md`：正文对比度 ≥ 4.5:1，键盘焦点可见，375 / 768 / 1024 / 1440 无横向滚动，适配 `prefers-reduced-motion`，全站禁用 emoji。

## 12. 关键决策

正式版落到 `docs/decisions.md`。

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D1 | 视觉不用教程的 Apple Cupertino Light，改用 `DESIGN.md`（维度分层） | 用户指定自有设计体系 |
| D2 | 收到首个 `token` 即切到结果页继续流式输出 | 研报在最终位置生成，避免生成完再整体跳屏 |
| D3 | 单用户本地应用，不做登录和管理后台 | 教程定位 Local-First；本期没有多用户需求 |
| D4 | 所有展示数字由后端计算，缺失就不显示 | 教程中共识度写死、相关性用固定值兜底，属于假数据 |
| D5 | 外部依赖先实测再接入（M0） | 教程中多个模型名、接口、包名未经验证 |
| D6 | 只保存成功完成的检索 | 中止和失败的结果不完整，存进历史会误导 |
| D7 | 功能与教程一模一样，原 P1（F11–F15、F21–F25）全部进入第一版 | 用户 2026-11-06 确认；D1、D4 的偏离仍保留（视觉自有、不用假数据） |
| D8 | 主调度 + 前端 session + 后端 session 三会话协作，每个里程碑结束产出学习文档 | 用户希望边做边学 AI 应用（RAG、编排）；规则见根目录 `CLAUDE.md` |

## 13. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| QuickRouter Jev 不存在或不可用 | F18 主方案失效 | 本地域名规则兜底已是 P0 方案；可改用 LLM 批量分类 |

| 外部 API 费用与限流 | 频繁调试产生费用 | 缓存 + 开发期 mock 模式 |
