# 数据库设计草案（M1）

> 版本：v1.0（定稿） · 2026-11-06 · 主调度审核定稿。
> 依据：`../docs/PRD.md` §7.1（search_history 草案）、§6（流水线产物）、`docs/接口设计-草案.md`（字段 camelCase ↔ snake_case 映射）、`docs/dispatch/M1-后端.md`。
> 标注：「A 实测」= 本机跑过；「提议」= 本文档建议，待主调度确认；「未确认」= 没证据，标出。
> 本文档只含设计与 SQL 文本，**不创建迁移文件**；M2 实现时把 V1__init.sql 落到 `app/db/migrations/`。

## 1. 选型与位置

- SQLite，Python 3.12.3 自带 sqlite 3.45.1（`uv run python -c "import sqlite3; print(sqlite3.sqlite_version)"` 实测）。
- 库文件：`backend/data/app.db`（`data/` 已进 `.gitignore`，确认）。
- 访问方式：`asyncio.to_thread` 包装同步 sqlite3（后端 CLAUDE.md 目录约定），单连接 + `WAL` 模式（**提议**，本地单用户写少读多，WAL 让历史列表查询不阻塞写入）。
- `PRAGMA foreign_keys = ON`、`PRAGMA journal_mode = WAL` 在连接建立时设置。

## 2. 迁移方案（轻量，自研）

不用 Alembic：单机 SQLite、表少、无团队协作冲突，Alembic 的 autogenerate 对 SQLite 的 ALTER 支持本来就弱（`batch_alter_table` 重建表）。改为 30 行左右的自研方案（**提议**）：

```
app/db/migrations/
    V1__init.sql
    V2__xxx.sql      # 之后递增
```

- 启动时对 `data/app.db` 依次执行未应用的 `V{n}__*.sql`（文件名前缀数字升序，重名/断号启动时报错退出，不猜测顺序）。
- `schema_version` 表记录已应用版本：

```sql
CREATE TABLE IF NOT EXISTS schema_version (
    version     INTEGER PRIMARY KEY,
    description TEXT    NOT NULL,
    applied_at  INTEGER NOT NULL
);
```

- **幂等**：每条迁移脚本自身用 `IF NOT EXISTS`；重复执行整条已应用脚本不会发生（版本表拦），手动重跑也因 `IF NOT EXISTS` 安全。
- **事务与回滚**：每个脚本在显式 `BEGIN ... COMMIT` 中执行（Python 端 `conn.executescript` 会先自动提交 pending 事务——实测确认——所以代码里先 `conn.execute("BEGIN")` 再 `executescript`）。SQLite DDL 是事务性的（实测：脚本中途失败，前面已执行的 `CREATE TABLE` 一并回滚，`schema_version` 不记该版本）。失败后应用拒绝启动，打印失败脚本名与错误，提示从备份恢复。
- **SQLite ALTER 限制**：`ALTER TABLE ADD COLUMN` 非幂等（重复列报错，实测）；`DROP COLUMN` 若被索引引用会失败（实测）。改列/删列统一走「建新表 → copy → rename」套路，写进对应 V 脚本。
- 备份：执行每条迁移前把 `app.db` 复制为 `app.db.bak.V{n}`（**提议**，单文件复制成本可忽略）。

## 3. 表清单

| 表 | 用途 |
| --- | --- |
| `search_history` | 一次完整检索的全部产物（唯一业务表） |
| `schema_version` | 迁移版本记录 |

中止/失败的检索**不入库**（决策 D6）；缓存命中的回放**不新插行**（历史记录指向首次计算那行，`cache_hit` 标在首次行上意为「该行是缓存产物」——**提议**，另一种口径是回放时给原行加计数，见 §6 待定项）。

## 4. `search_history` 字段

`V1__init.sql` 完整文本（`%TEMP%\m1final\t.py` 实测：建表、重跑幂等、失败回滚、约束拒绝脏数据、覆盖索引生效）：

```sql
CREATE TABLE IF NOT EXISTS search_history (
    id                TEXT    PRIMARY KEY CHECK (substr(id, 1, 5) = 'hist_'),
    query             TEXT    NOT NULL CHECK (length(query) BETWEEN 1 AND 500),
    focus_mode        TEXT    NOT NULL CHECK (focus_mode IN ('academic', 'code', 'web')),
    requested_engine  TEXT    NOT NULL CHECK (requested_engine IN ('tavily', 'deepseek')),
    engines_used      TEXT    NOT NULL CHECK (json_valid(engines_used) AND json_type(engines_used) = 'array'),
    degraded          INTEGER NOT NULL DEFAULT 0 CHECK (degraded IN (0, 1)),
    scope_filters     TEXT    NOT NULL DEFAULT '[]' CHECK (json_valid(scope_filters) AND json_type(scope_filters) = 'array'),
    rewritten_queries TEXT    NOT NULL CHECK (json_valid(rewritten_queries) AND json_type(rewritten_queries) = 'array'),
    stage_timings     TEXT    NOT NULL CHECK (json_valid(stage_timings) AND json_type(stage_timings) = 'object'),
    trace_events      TEXT    NOT NULL CHECK (json_valid(trace_events) AND json_type(trace_events) = 'array'),
    raw_sources       TEXT    NOT NULL DEFAULT '[]' CHECK (json_valid(raw_sources) AND json_type(raw_sources) = 'array'),
    sources           TEXT    NOT NULL CHECK (json_valid(sources) AND json_type(sources) = 'array'),
    report_text       TEXT    NOT NULL,
    citations         TEXT    CHECK (citations IS NULL OR (json_valid(citations) AND json_type(citations) = 'array')),
    takeaways         TEXT    CHECK (takeaways IS NULL OR (json_valid(takeaways) AND json_type(takeaways) = 'array')),
    follow_ups        TEXT    CHECK (follow_ups IS NULL OR (json_valid(follow_ups) AND json_type(follow_ups) = 'array')),
    consensus         TEXT    CHECK (consensus IS NULL OR (json_valid(consensus) AND json_type(consensus) = 'object')),
    latency_ms        INTEGER NOT NULL CHECK (latency_ms >= 0),
    token_stats       TEXT    CHECK (token_stats IS NULL OR (json_valid(token_stats) AND json_type(token_stats) = 'object')),
    llm_model         TEXT,
    source_count      INTEGER NOT NULL CHECK (source_count >= 0),
    char_count        INTEGER NOT NULL CHECK (char_count >= 0),
    cache_hit         INTEGER NOT NULL DEFAULT 0 CHECK (cache_hit IN (0, 1)),
    created_at        INTEGER NOT NULL,
    updated_at        INTEGER NOT NULL
);

CREATE INDEX IF NOT EXISTS idx_search_history_created_at
    ON search_history (created_at DESC, id DESC);
```

### 4.1 列说明

| 列 | API 字段 | 说明 |
| --- | --- | --- |
| `id` | `id` | `hist_` + ULID/UUID4 hex（实现时定，CHECK 只锁前缀） |
| `query` | `query` | 用户原始查询 |
| `focus_mode` / `requested_engine` | `focusMode` / `engine` | 请求枚举 |
| `engines_used` | `enginesUsed` | `["tavily","deepseek"]` 子集，双引擎实际用了谁 |
| `degraded` | `degraded` | 0/1；降级原因明细在 `trace_events` 里 |
| `scope_filters` / `rewritten_queries` | `scopeFilters` / `rewrittenQueries` | JSON 数组 |
| `stage_timings` | `stageTimings` | `{rewritingMs, searchingMs, reasoningMs, generatingMs, finalizingMs, firstTokenMs}` |
| `trace_events` | `traceEvents` | 完整 trace 事件数组（历史详情页重放观测台） |
| `raw_sources` | —（仅详情接口） | RawSource 数组（精简 SourceCard） |
| `sources` | `sources` | SourceCard 数组（§4.1 接口草案），**含 `index`**；passage 存的是 ≤1500 字符的清洗版 |
| `report_text` | `report` | 研报 Markdown 原文（含 openui-lang 围栏） |
| `citations` | `citations` | 接口草案 §7.2 结构；解析失败/无引用为 NULL |
| `takeaways` / `follow_ups` / `consensus` | 同名 | finalization 产物；调用失败为 NULL |
| `latency_ms` | `latencyMs` | 端到端耗时 |
| `token_stats` | `tokenStats` | `{promptTokens, completionTokens, totalTokens, promptCacheHitTokens, promptCacheMissTokens}` 的 snake_case |
| `llm_model` | — | 实际生成模型名（`deepseek-flash`），便于日后换模型回溯 |
| `source_count` / `char_count` | `sourceCount` / `charCount` | 冗余统计列，列表页免解析 JSON |
| `cache_hit` | `cacheHit` | M1 定稿：缓存回放新插一行并标 `cache_hit=1`，首算行保持 0 |
| `created_at` / `updated_at` | `createdAt` / `updatedAt` | INTEGER 毫秒时间戳；API 序列化为 ISO 8601 |

### 4.2 为什么统计列冗余

`source_count`/`char_count`/`latency_ms`/`cache_hit` 在 JSON 里都有，但历史列表页（`GET /api/history`）需要它们做展示和将来的排序/筛选，每条都 `json_extract` 太贵——冗余成标量列，写入时和 JSON 同源生成，不会漂移。

### 4.3 索引

- `idx_search_history_created_at (created_at DESC, id DESC)`：历史列表「按时间倒序 + 主键做游标稳定排序」的覆盖索引（实测查询计划为 COVERING INDEX scan）。`page` 分页用 `LIMIT/OFFSET` 或游标，索引都适用。
- 暂无其它索引：`q` 的 LIKE 前缀模糊用不上索引，数据量小（本地单用户）可全表扫，后续量大再加 FTS5（**提议**：V2+ 再议）。

## 5. 枚举值汇总

| 字段 | 值 | 出处 |
| --- | --- | --- |
| `focus_mode` | `academic` `code` `web` | PRD §8.2 |
| `requested_engine` / `engines_used[]` | `tavily` `deepseek` | 双引擎名（`deepseek` = DeepSeek 检索，命名与 LLM 提供方区分问题见 §6） |
| `scope_filters[]` | `preprint` `code` `spec` `docs` `blog` | 接口草案 §4.5 |
| SourceCard.`category` | 同上五类 | 接口草案 §4.5 |
| SourceCard.`categorySource` | `rule` `model` | 接口草案 §8 |
| trace.`step` | `rewriting` `searching` `reasoning` `generating` `finalizing` | 接口草案 §3.1 |
| trace.`status` | `start` `end` `degraded` | 接口草案 §3.1（定稿） |

枚举写进 CHECK 约束（上表前两项已写）。JSON 列内部枚举（category 等）DB 不校验，由应用层 + `json_valid` 兜底——SQLite CHECK 解析 JSON 数组内元素太贵（**提议**）。

## 6. 需要主调度决定

| # | 事项 | 本草案建议 |
| --- | --- | --- |
| 1 | `cache_hit` 口径：标在首算行 vs 回放行计数 | 标在首算行（回放不插行），历史页「这次搜索是缓存结果」语义成立 |
| 2 | 引擎命名：`deepseek` 同时指 LLM 提供方与 DeepSeek 检索 | 保持 `deepseek`（PRD §7.1 草案即用此名），LLM 侧用 `llm_model` 列区分 |
| 3 | `id` 生成：ULID vs UUID4 | ULID（时间有序，辅助排序）；实现时定 |
| 4 | `data/` 目录与备份文件 | `data/app.db`、`data/app.db.bak.*`，全进 `.gitignore` |
| 5 | `raw_sources` 是否入库 | 入库（详情页/调试要原始批次对照 ranked），体积可接受 |
| 6 | LIKE 搜索 vs FTS5 | V1 用 LIKE；FTS5 留待 V2+ |
| 7 | `report_text` 大小 | 不设上限 CHECK；实测研报量级 KB–几十 KB，SQLite 无压力 |
| 8 | 时间戳精度 | INTEGER 毫秒（与 API 的 `*Ms` 字段一致） |

## 定稿修订（主调度，2026-11-06）

- `trace.status` 统一为 `start/end/degraded`。
- `cache_hit` 定为缓存回放新插一行并标 1，记录本次真实回放耗时；首算行保持 0。
- 采纳草案 §6 其余建议：ULID、raw_sources 入库、V1 用 LIKE、毫秒时间戳。
