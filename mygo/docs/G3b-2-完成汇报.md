## 知识点素材

- 缓存回放为什么耗时必须实测：缓存里存的是产物（正文、信源、引用），不是耗时。若把首次的 24 秒原样回放，界面会显示一个这次根本没发生的数字，用户据此判断性能就会被误导（决策 D4）。`replay` 用 `time.Now()` 在每个阶段现场计时，`snapshot.go`。
- SQLite 参数绑定与 JSON 列序列化纪律：SQL 文本里只有 `?`，所有值走参数绑定，杜绝拼接注入。JSON 列先在 Go 里 `json.Marshal` 成字符串再绑定，表上的 `CHECK (json_valid(...))` 兜底；空切片用 `arr()` 保证写成 `[]` 而不是 `null`，否则 `json_type = 'array'` 约束会拒绝。`store.go`、`snapshot.go`。
- 写库失败不能静默：Python 版出过这个错。这里 `persist` 失败时记 `level=error` 并带 `%T` 与错误内容，响应照常返回，测试 `TestHistoryWriteFailureDoesNotBreakResponseAndIsLogged` 挡住。
- 函数级对齐为什么比端到端可靠：端到端结果受搜索引擎返回波动和 LLM 改写随机性影响，差异无法归因。固定一份真实原始输入分别喂两版重排，输入相同则差异只能来自算法，容差 1e-6。`rank_parity_test.go`。
- 回放的 trace 要自己记录：回放历史行的 `trace_events` 存的是回放自己的 trace，而不是空列表；第一版漏记，测试 `TestHistoryRowsForFreshAndReplay` 发现后修正。
