## 任务 1：Channel 流式推送

```text
BURST done: sent=2000 got=2000 dropped=0 reorder=0 firstAt=9.4ms total=23ms goMillis=4 sendErr=false
FLOW done: got=12 MiB=3.0 total=1575ms        ← 页面慢消费 120ms/帧，Send 背压生效
Slow ctx canceled after 3 sends: context canceled   ← 页面 break 后
SLOW done: pageGot=3 call=rejected: context canceled
```

- 2000 小包 1–20ms 间隔：**零丢包、零乱序**，首包 9.4ms，总 23ms。
- 12×256KiB=3MB 超过 1MiB 窗口：`channel.send` 的 `c.sent-c.taken >= channelWindow`（`channel.go:246`）触发等待，内存不暴涨。
- 页面 `break`/关 Channel → `close(closedByPage)` → `c.cancel()`（`channel.go:283`）→ Go `Send` 返回 `ErrChannelClosed`、调用 ctx 取消、promise rejected。

**结论**：`mygo.Channel[StreamFrame]` 可承载检索流。无需 SSE 心跳和 runId——Channel 保序且断连即取消；前端仍保留 runId 守卫防同页连搜（PRD §4.2）。

## 任务 2：StreamFrame 联合体生成 TS

**写法 A（采用）**：单结构体 `Type string` + 全可选字段（`omitempty`/指针）。生成：

```ts
export interface StreamFrameA {
  type: string;
  trace?: TracePay;
  sources?: Source[];
  token?: string;
  related?: string[];
  done?: DonePay;
  error?: string;
}
```

前端 `switch (f.type)` 正常收窄。**写法 B（`Payload any`）**：mygo 接受不报错，但生成 `payload?: unknown`——字段信息全丢，前端拿不到补全，不可用（违背类型安全）。

**结论**：采用写法 A。`tsgen.Validate`（`internal/tsgen/types.go:66`）只拒 `chan/func/complex/unsafeptr` 和非法 map key；`interface{}` 不拒但退化为 `unknown`，不要依赖它做联合。

## 任务 3：取消传播

5 并发真实 Tavily（`httptrace` 记 `conn acquired`/`request failed`），页面 2 秒后 `ch.close()`：

```text
[tavily:probe query 0..4] conn acquired        ← 5 个全部发出
[spike:page] cancel: closing channel now
[tavily:probe query *] request failed: ... context canceled   ← 5 个全部取消
[burst] finished: started=5 done=0 canceled=5
```

**铁证**：`started=5 done=0 canceled=5`，断开后零新外部调用。**结论**：`ctx` 派生的并发外部调用在 Channel 关闭后全部被取消。流水线所有外部调用必须用该 `ctx` 派生，不用 `context.Background()`（CLAUDE.md §5.3 已强制）。

## 知识点素材

- **Channel 背压**：`channel.go:126 channelWindow=1<<20`，`send` 在 `c.sent-c.taken >= channelWindow` 时 `c.cond.Wait()`（`channel.go:246`），页面每半窗口 ack 一次（`ack` `channel.go:267`）。主线程不阻塞（`isMainThread` 守卫）。
- **取消传播**：`close(closedByPage)` 在持锁下先 `c.cancel()`（`channel.go:283`）再置 `closed`；`context.AfterFunc(ctx,...)`（`channel.go:189`）让导航/关窗走 `closedByLoss`。Send 检查 `c.closed || c.ctx.Err()`（`channel.go:250`）。
- **绑定发现**：`mygo.Bind` 运行期反射（`ipc.go:124 bind` → `newMethod` `ipc.go:204`），`generate` 是「编译 + `MYGO_GENERATE` env 跑二进制收集」（`cmd/mygo/proc.go:191 generateBindings`）。多返回值只支持 `(value, error)`，error 非 nil → Promise reject（`ipc.go:227`）。
- **UTF-16 偏移**：`internal/textutil/utf16.go UTF16Offsets`——rune `>0xFFFF` 计 2，对应 JS `String.length`/`slice` 的 UTF-16 码元口径；`sentences.go SplitSentences` 返回 rune 索引，引用定位先 rune 定位再经偏移表转 UTF-16。
- **生成物边界**：`src/mygo.ts` 由 `MYGO_SPIKE` 门控 —— 不带 probe 时 generate 不含 Spike 方法，正式客户端干净（实测 grep=0）。
