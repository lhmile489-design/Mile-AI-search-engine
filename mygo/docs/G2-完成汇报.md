## 完成内容

### 1. Go 契约类型与绑定桩（上一阶段已就位，本轮确认）

- `internal/contract/contract.go` — 事件载荷类型（`StreamFrame`/`SearchRequest`/`SearchResult`/`HistoryItem`/`AppConfig`/`SettingsRequest` 等），与 `docs/接口设计.md` 对齐。
- `internal/service/search.go` — `SearchService` 绑定，`search` 返回 `errors.New("not implemented (G3): pipeline arrives in the next milestone")`；非流式方法同样返回该字符串。`main.go` Bind 注册。
- 桩的语义：前端拿到的是真实 Go 调用错误（CallError），不是假数据；界面透出 `not implemented` 原文而不是笼统「连接失败」。

### 2. `src/lib/transport.ts`（核心新增）

- `SearchTransport` 接口：`openStream + getConfig + getSuggestions + listHistory + getHistory + deleteHistory + saveSettings` —— **前端与后端的唯一访问面**。
- `frameToEvent(frame: StreamFrame): SseEvent | null`：把 Go 的 writing-A 单结构帧映射回前端的 discriminated union `SseEvent`。`sources` 帧的 `raw`/`ranked` 数组合并回 `items` union；枚举字段（engine/step/category）在边界一次性 `as` 收窄，注释说明原因。
- `openMyGoStream`：`new Channel<StreamFrame>()` 传给 `SearchService.search(req, ch)`，`for await` 消费，45s 看门狗，CallError → `{kind:"api", message: err.message}`。
  - **settled-promise 模式**：`done` 用 `.then/.catch` 捕获进 `settled` 变量，`for await` 早退（abort）时不会 unhandled rejection；`for await` 结束后只在未 settled 时 `await done`。
  - **fail-before-stop 顺序**：`settled && !settled.ok` 时先 `fail(...)`（fail 内部调 stop），成功路径才 `stop()`。反过来会让 `fail` 的 `if(dead) return` 把自己杀掉 —— 这是实测出来的 bug。
- `resolveTransport()`：缓存 Promise；`import.meta.env.DEV && import.meta.env.VITE_USE_MOCK === "1"` 才加载 mock 分支，生产构建里该分支被 DCE。
- `resolveOpenStream()` 兼容垫片：controller 只改一行调用点。

## 知识点素材

- **Channel 帧 → reducer 事件的适配**：`frameToEvent` 在 `src/lib/transport.ts`；Go 侧是 writing-A 单结构（`type` + 可选字段），前端是 discriminated union。边界一次性 `as` 收窄，下游全部用窄类型。
- **为什么后端访问收敛成一个 `SearchTransport` 接口**：所有后端调用（流式 + 非流式）都走这一个接口，mock/真实实现只在 `resolveTransport()` 一处切换；组件、hook、store 完全感知不到来源 —— 这是「mock 只在 src/mocks/ 且不进生产包」能成立的前提。
- **mock 如何被挡在生产包外**：`import.meta.env.DEV && import.meta.env.VITE_USE_MOCK === "1"` 是编译期常量判定，Vite 在 build 时把整段分支 DCE；`grep dist/` 验证 mock 标识符 0 命中。
- **settled-promise 模式**：`for await` 消费 channel 时若 abort 早退，`done` 可能仍处于 pending/rejected；用 `.then/.catch` 先把结果捕获进变量再 `await`，避免 unhandled rejection 同时保留错误信息。
- **Channel 取消语义**：`channel.close()` 会取消该次调用的 `ctx`；Go 侧方法返回即关闭 channel，所以 mock 的 `finally { ch.close() }` 必须存在，否则 `for await` 永远挂着。
